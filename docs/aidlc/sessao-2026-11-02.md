## Para amanhã

### 1. Subir para a nuvem
Pendências do usuário:
- Rodar `! npx supabase login`.
- Informar o **Project ref**.
- Informar `CONSELHO_VALIDACAO`: `desligada`, `simulada` ou `real`. O `real` bloqueia o cadastro, porque ainda não há provedor de consulta ao conselho.
- Informar `SITE_URL` (a URL do front na Vercel).

Depois disso, nesta ordem:

| Passo | Comando | O que faz |
|---|---|---|
| 1 | `npx supabase link --project-ref <ref>` | vincula a pasta ao projeto da nuvem (pede a senha do banco) |
| 2 | `npx supabase db push --dry-run` | só lista as migrations que seriam aplicadas, para conferir |
| 3 | `npx supabase db push` | aplica as migrations no banco da nuvem |
| 4 | `npx supabase functions deploy cadastrar-profissional` | publica a Edge Function do cadastro com convite |
| 5 | `npx supabase secrets set CONSELHO_VALIDACAO=... SITE_URL=...` | configura a função |

O `seed.sql` (usuários de teste) **não** vai para a nuvem.

### 2. SMTP real
Configurar um provedor (Resend, SendGrid…) em `[auth.email.smtp]` e no painel da nuvem, para os convites chegarem na caixa real. Localmente, eles caem no Mailpit.
